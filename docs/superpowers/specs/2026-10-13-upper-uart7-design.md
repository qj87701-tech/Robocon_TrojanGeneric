# UART7上位机32字节接收与USART10打印规格

## 1. 目标与边界

UART7接收上位机固定32字节报文，封装原始数据和通信状态；USART10提供可独立调用的非阻塞打印函数，便于双方联调。用户同步修改上位机发送端。

- 不将接收数据接入底盘、电机、遥控或机构控制。
- 不除以1000，不进行物理单位换算、滤波、限幅或动作解释。
- CRC16计算与检查能力封装好，接收校验默认关闭。
- 不新增RTOS、任务队列、SUBS、通用通信管理器或上位机应答协议。
- 不使用空的`tsk_upper`目录，不删除该目录。
- 不修改参考工程、CubeMX配置、串口驱动或现有电机保护。

## 3. 32字节线协议

下标从0开始，总长度包含帧头、CRC预留和帧尾。只支持本次32字节格式，不自动兼容旧10或22字节帧。

| 字节 | 内容 | 解释方式 |
|---|---|---|
| 0–1 | 帧头 | 固定`55 AA` |
| 2–3 | 原始Y速度字段 | 小端、有符号16位整数 |
| 4–5 | 原始X速度字段 | 小端、有符号16位整数 |
| 6–7 | 原始W速度字段 | 小端、有符号16位整数 |
| 8–19 | 原有12个数据字段的位置 | 12个原始字节，不解释为旧机构动作 |
| 20–28 | 扩展数据 | 9个原始字节，未使用字段发送0 |
| 29–30 | CRC16预留 | 低字节在29，高字节在30 |
| 31 | 帧尾 | 固定`77` |

速度字段保留整数值，包括负值及`-32768`、`32767`边界，不标注为m/s、rad/s或rpm。保留最近一帧全部32字节，便于核对原始报文。载荷可以包含`55 AA`或`77`，不能看到这些字节就提前截断帧。

CRC关闭时字节29–30不参与接收判定，上位机可以填0；这些字节仍被原样保存。

## 4. CRC16接口

采用`CRC-16/CCITT-FALSE`：多项式`0x1021`，初值`0xFFFF`，输入和输出均不反射，最终异或值`0x0000`。报文计算范围为字节0–28，共29字节，不包含CRC字段或帧尾。

在`pro_upper`封装计算函数和帧检查函数；接收类提供明确的校验启用接口，初始化默认关闭，避免后续启用时改写解析器。运行中切换校验策略时，丢弃尚未完成的候选帧，避免混合两种策略。

CRC关闭时，接收成功只代表长度及帧头、帧尾符合格式，不能证明载荷未损坏。调试状态必须打印CRC是否启用，不把未校验报文标为CRC通过。启用后，CRC失败帧不得发布数据或刷新在线时间。

## 5. 文件职责与接口

### `User_File/1_Middleware/Protocol/pro_upper/pro_upper.h/.cpp`

新增协议类`Class_Upper`及对象`Upper`，保持HI06与中科大参考的头文件分区、类组织、命名和中文Doxygen注释。

头文件集中声明帧常量、缓存及超时常量、状态枚举、数据结构、类接口、对象声明和CRC函数；实现文件保留对象的唯一实例定义及函数实现。速度、12个原始数据字节、9个扩展字节和32字节原始帧均可读取，不增加旧机构专用控制接口。

接口职责：

- `Init()`：清空缓存、数据和统计，初始离线且数据无效，CRC默认关闭。
- `UART_RxCpltCallback(Buffer, Length)`：仅将接收字节写入固定缓存，不解析、不打印、不驱动电机。
- `TIM_10ms_PeriodElapsedCallback()`：前台组帧、发布完整数据、维护超时状态。
- `Get_Data()`、`Get_Status()`：获取最近完整帧数据及在线状态；数据中提供有效性、更新时间和接收统计。
- `Set_CRC_Check_Enable(Enable)`：切换是否校验CRC，默认不启用。

只使用静态存储或固定大小成员数组，不使用动态内存和复杂容器。沿用HI06单写入端、单读取端缓存模式，避免ISR与前台索引竞争。

包含协议头文件；初始化`Upper`后注册UART7回调；回调仅转发给协议对象。现有10ms前台回调调用协议解析函数，不改变底盘、DM、VESC和VOFA调用周期。

第一个打印原始X/Y/W整数、12个数据字段和9个扩展字段；不附加未经约定的单位。第二个打印在线状态、数据有效性、数据年龄、CRC启用状态，以及字节、接收帧、格式错误、CRC错误、缓存溢出计数。

## 6. 接收、恢复与状态

- 一次DMA回调可能包含半帧、一帧或多帧；协议层按字节流恢复固定长度帧。
- 噪声、非法帧尾或CRC失败后，重新搜索下一候选帧头，保留可能属于后续完整帧的数据。
- 完整帧通过当前启用的检查后，才一次性更新数据、更新时间、有效性和帧计数。
- 缓存溢出时记录错误，丢弃无法保证完整性的候选数据并恢复同步，不能拼接缺失字节发布伪帧。
- 诊断离线超时集中配置，初始建议500ms；这是新模块的诊断默认值，不是推断出的上位机发送周期，后续按实际发送周期调整。
- 超时后标记离线和数据无效，保留最后一帧供诊断；下一有效完整帧恢复在线。使用无符号时间差处理时基回绕。
- 无效帧或仅收到部分字节不能续期在线状态。本模块掉线不改变现有电机状态，因为本阶段不参与控制。
